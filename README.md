## チームのルール
 
1. **main に直接書かない**：必ず枝（ブランチ）を作って、PR を通す
2. **枝の名前は `feature-○○`**：作業が分かる名前にする（例：`feature-shop-about`）
3. **PR に説明を書く**：何をしたか、確認したことを書く
4. **決めた人数の Approve でマージ**：自分の PR は自分で Approve できない
5. **始める前に main をプル**：main が進んでいたら取り込む
6. **`style.css` は声をかけてから**：ぶつかったら全員で相談して直す
## 1ページを作るときの流れ
 
この流れを、ページが完成するまで何度でも回します。
 
1. `main` をプルして最新にする
2. VS Code の左下から `feature-○○` の枝を作る（作業が分かる名前）
3. 自分のページを作る。ブラウザで表示を確かめながら進める
4. ステージしてコミットし、枝を発行（Publish Branch）する
5. GitHub で PR を作り、説明を書く
6. ほかのメンバーにレビューしてもらい、Approve されたらマージする
7. `main` に戻ってプルし、使い終わった枝を消す
> 1回の PR は小さく。ページ全部ができる前でも、区切りのよいところで PR にしましょう。
